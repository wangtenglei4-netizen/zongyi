# 镜中局 · 本地原型

一个舞台大屏和一个导播台，用于八人抽身份、标记队长、第 2、4 轮队伍分数展示和魔镜问话。

## 启动

macOS 可以双击「启动演示.command」。需要 Node.js 20.9 或以上，也可在项目目录运行：

```sh
npm ci
npm run dev
```

在浏览器打开终端显示的 `Local` 地址，默认是 http://127.0.0.1:3000。首页是导播台，点「打开舞台大屏」进入 `/stage`，将该窗口移至扩展显示器并全屏。结束时在终端按 Control + C。

## 角色头像

在导播台点击「角色头像」，分别上传黑队平民、白队平民、黑队卧底和白队卧底的图片。卧底头像按实际效力的队伍配置。支持 PNG、JPG 和 WebP，每张最多 4 MB。亮身份时显示头像，未上传时使用默认图标。图片保存在 `.zongyi/avatars/`，重置本局后仍保留。

## 演示顺序

1. 导播代嘉宾选信封，确认其他人转身后点「亮身份」。看完收起，等舞台窗口确认收牌后再切下一位。
2. 八人抽完后，根据现场投票结果为黑白两队各标记一位队长。
3. 第 2、4 轮选择队伍，分别填写「分数」与「实际分数」后发布。
4. 两次队伍分数发布后进入魔镜。每队可查验一次，确认后被查验者姓名与身份会公开显示在大屏魔镜里。

录入的队伍分数由工作人员预先计算。舞台和导播使用同一台电脑的两个窗口，本地默认将场次写入项目目录下的 `.zongyi/show.json`。配置 `KV_REST_API_URL` 和 `KV_REST_API_TOKEN` 后，场次保存在 Upstash Redis。首次打开导播台时，可从同一浏览器旧版 Demo 的存档恢复抽签和查验记录。旧版四轮计分的存档需要按新版规则重新录入并发布第 2、4 轮分数，身份、队长和已使用的魔镜记录会保留。演示前可通过「重置本局」开启新局。

本地服务绑定回环地址。配置 `SITE_PASSWORD` 后，导播台、大屏和同步接口都需要站点口令。现场投屏时仅共享舞台窗口。待办和规则细节见 [plan.md](plan.md)。

运行 `npm test` 验证游戏规则，运行 `npm run build` 检查构建。

## 场次同步

导播台和舞台各保持一条 SSE 连接，连接成功后会收到当前场次。导播操作和舞台自动收牌确认仍通过 HTTP 提交。配置 Redis 时，更新场次后通过 Pub/Sub 通知订阅端读取对应版本。纯本地模式在同一个 Node 进程内通知两个页面。

空闲时连接只发送保活注释。Vercel 上连接最多运行约 4 分 45 秒后由服务主动关闭，浏览器自动重连并读取最新场次。短暂断开时大屏会立即收起当前身份。
